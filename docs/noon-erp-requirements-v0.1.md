## 0. 一页结论（先看这里）

> **① 对标的是「模块」，不是「平台」。** 万墨 Wimoor 是**只做亚马逊、且明确不计划扩展其他平台**的 ERP（SpringBoot + SaaS，源码开放），它的价值在于把「进销存 → 采购补货 → 利润核算」这条主干做得很扎实。但直接照搬到 Noon 会漏掉大约 10 块 Noon 特有的东西，而且**有些功能在 Noon 上根本做不了全自动化**。

> **② 需求范围建议：MVP 只做主干 + Noon 适配层。** 主干 = 商品/供应商/采购/多仓库存/订单履约/结算对账/SKU 利润/补货建议。刊登与广告做成「**AI 生成 + CSV 导入 + 报表回读**」的半自动，不投入做全自动化改造。

> **③ 项目最大的技术风险不是架构，是 Noon 的接口开放性。** Noon 宣称有 API Platform（catalog / orders / fulfillment / event notifications），但**没有公开开发者门户、没有公开的鉴权方案、限流、错误码和沙箱**，需要提工单申请、在 FBPI onboarding 阶段才拿到 staging 凭据；且 FBPI 文档明确写了「**商品创建不支持 API，必须在 Seller Lab 操作**」。所以集成层必须做成**可插拔适配器 + API/CSV/文件三通道**，不能把业务代码焊死在某个接口上。

> **④ 架构按你定的来：** Java 单体（SpringBoot）+ 单库 + 一个 `NoonAdapter` 适配层；AI 二开走**外挂 Agent**，只读取视图和写「建议单」，**不直接改库存、不改财务账、不侵入核心代码**。

> **⑤ 最需要你拍板的一件事：** 先按哪种履约模式建模（Global 中国直发 / FBN / FBP 自建仓）。因为 **Global 是「供价结算」，FBN/FBP 是「佣金结算」，这是两套完全不同的利润模型**，不能共用一张利润表。详见 §3 和 §8-Q1。

| F-08 | Noon 无公开开发者门户 / 无公开鉴权、限流、错误码、沙箱、SLA；API Platform 只被「描述」未被「发布」，需提 support ticket 给 integrations team；staging 凭据在 FBPI onboarding 后才给 | 集成排期存在不可控风险 → 适配器必须可替换，且要准备 CSV 降级方案 | [8] |
| F-09 | Seller Lab 提供 CSV 导入：价格、价格区间、库存、SKU 改名/删除、批量建 SKU、条码映射、多类目批量刊登；**单次导入价格变动幅度上限 30%** | 调价要拆批，系统需内置「单次 30% 上限」校验与任务拆分 | [8] |
| F-10 | **结算：每周三出 statement，UAE/KSA 于次周周四付款**；账单含当期已妥投订单 + 以前账单已付但本期新发生的退货 + 平台费用 + 损货/退货罚金；周账单须为正、达最低打款门槛；**账单争议须在生成日起 15 天内提出，逾期不受理** | 财务模块必须有「账单周期 + 15 天争议倒计时 + 差异核对」功能，这是刚需不是加分项 | [10] |
| F-11 | **FBN 仓储费出的是单独的月度 storage statement**（通常次月第二周），与周结算账单分离 | 对账要匹配两类账单，不能只做一份 | [S-4] |
| F-12 | 费用结构：类目佣金（差异极大，如服饰 27%、香水 14%–15%、家居 14%–15%、手机 5%–6%、其他约 14%；沙特每单最低 1 SAR）+ FBN 出库费（按尺寸/重量/价格档）+ 仓储费（UAE AED 1.75 / ft³、KSA SAR 2.75 / ft³，>365 天库龄 25 / ft³）+ 退货管理费（15 或佣金的 20%，取低）+ DirectShip 费；**所有费率报价均不含 VAT** | 费用字典必须「按类目 × 站点 × 履约模式 × 时间版本」可配置，并保留历史版本以重算历史利润 | [11][S-4] |
| F-13 | 定价机制：UAE 价格为基准，跨境到沙特的 SAR 价由 noon 定价引擎换算（剔除 5% UAE VAT → 经 USD 转 SAR → 加 15% 沙特 VAT + 跨境物流费 + 进口关税）；GCC lane 另有 5%「Import VAT recovery」；**卖家不自行设置 SAR 价** | 定价模块应「以 UAE 定价倒推贡献毛利 + 预估 SAR 到手价」，而不是双站点独立定价 | [S-4] |
| F-14 | 内容：**英语必填、阿拉伯语选填**，但 Noon 明确不做翻译，且**英文-only 的 SKU 可能不出现在阿语站**；店名需英阿双语 | 商品主数据要存双语字段；AI 生成英阿双语文案是最贴合的外挂场景之一 | [S-3][S-4] |
| F-15 | 广告：Seller Lab 内 Sponsored Products，CPC、**第一价拍卖（出多少付多少）**，自动/手动关键词、动态出价、搜索位加价，广告费**从每周回款中自动扣除**；无公开的投放 API | 广告模块做「报表导入 → 归因到 SKU 利润 → ACOS/ROAS 分析」，不做投放控制 | [S-6][S-7] |
| F-16 | 履约 SLA：自发货需 24h 内确认/发货，连续 3 次违约影响卖家评分与曝光；退货窗口 15 天（FBP 文档写 14 天，见冲突项）；退货按等级由 Seller Protection Fund 补偿，争议/申诉窗口 7 天（Directship）/14 天（RTV 与分级） | 订单需 SLA 倒计时看板；售后需「窗口期 + 申诉截止日」提醒 | [S-8][S-9][S-10] |
| F-17 | 大促节奏：斋月/开斋节、Yellow Friday（约 11 月下旬）、White Friday、11.11 预热；FBN 基本是参加大促的前提 | 补货模型必须支持「大促系数」和提前备货天数 | [S-6][S-11] |
| F-18 | 合规字段：沙特 SASO、阿联酋 ECAS、部分品类 Halal、HS Code、原产地、品牌授权链路；VAT 由 ZATCA（KSA）/ FTA（UAE）按季申报 | 商品主数据需合规字段与到期提醒；财务需 VAT 归集口径 | [S-2][S-4] |

## 2. 业务全景：一条闭环，九个环节

```
① 选品/开发  → ② 供应商&采购 → ③ 头程/入仓 → ④ 刊登/定价 → ⑤ 订单/履约
      ↑                                                              ↓
   ⑨ 补货/调拨 ← ⑧ 利润/绩效 ← ⑦ 结算/对账 ← ⑥ 售后/退货  ←──────┘
```

| # | 环节 | 触发 | 主责角色 | 关键输入 | 产出单据/数据 | Noon 特有动作 |
| --- | --- | --- | --- | --- | --- | --- |
| ① | 选品与产品开发 | 市场机会 / 双站点数据对比 | 运营 | UAE+KSA 品类销量、价格带、竞品 | 开发单、SKU 编码、目标毛利 | 双市场对比不能把 AED 与 SAR 直接相加；需汇率与 VAT 归一 |
| ② | 供应商与采购 | 补货建议 / 新品首单 | 采购 | 供应商报价、MOQ、交期 | 采购单 → 审批 → 到货 → 质检 → 采购结算 | 认证资料（SASO/ECAS/Halal）、品牌授权链路归档 |
| ③ | 头程与入仓 | 采购到货 | 物流/仓库 | 装箱单、HS Code、原产地 | 入库单 / 调拨单 / **ASN 货件** / 在途跟踪 | Global 发深圳中转仓；FBN 走 ASN 入官方仓；FBP 入自有海外仓；收货差异需回写 |
| ④ | 刊登与定价 | 货齐 / 新品 | 运营 | 双语素材、类目属性、UAE 基准价 | Partner SKU、Listing、价格/库存推送 | EN 必填 AR 选填；CSV 单次调价 ≤30%；沙特价由平台换算；标题 SEO 词库 |
| ⑤ | 订单与履约 | 买家下单 | 仓配 | webhook 订单 / Seller Lab 导出 | 出库单、AWB、manifest、状态回写 | 24h SLA 倒计时；FBPI webhook 需 ACK（Pending→Acknowledged，失败重试到 Killed）；COD 状态 |
| ⑥ | 售后与退货 | 妥投后 15 天内 | 客服/仓 | 退货申请、分级结果 | 退货单、二次上架/报废单、申诉单 | 退货管理费、Seller Protection Fund 分级、7/14 天申诉窗口、RTO |
| ⑦ | 结算与对账 | 每周三 | 财务 | 周 statement、月度仓储 statement、回款流水 | 结算单、差异清单、争议单 | **15 天争议倒计时**；两类账单分别核对；广告费从回款扣 |
| ⑧ | 利润与绩效 | 结算后 / 按需重算 | 财务/运营 | 订单收入 + 全量费用 + 采购成本 | SKU/店铺/站点利润表、利润月报、库存货值 | Global 供价模型与 FBN/FBP 佣金模型分账；自定义公式 + 重算 |
| ⑨ | 补货与调拨 | 可售天数低于阈值 / 大促前 | 运营/采购 | 日均销量、在途、库龄、交期 | 补货建议单 → 采购单 / 调拨单 | 按「站点 × 履约模式」分别算；斋月/Yellow Friday 系数 |

**闭环关键**：万墨最强的是把 ②→③→⑧→⑨ 串成一条自动线（销量驱动补货、补货驱动采购、采购驱动入库、入库成本进利润）。这条主干我们要完整保留，**其余环节围绕 Noon 做加减法**。

## 3. 三种履约模式：建模差异（最影响数据结构）

| 维度 | Global / NGS 中国直发 | FBN 官方仓 | FBP（含 FBPI）自有仓 |
| --- | --- | --- | --- |
| 库存归属 | 国内仓 / 深圳中转仓 | Noon 官方仓（UAE / KSA 分开） | 自有或第三方海外仓 |
| 结算方式 | **供价结算**：无佣金、无仓储费、无出仓费；供价 = 成本 + 利润 + 到深圳仓运费 | **佣金结算**：类目佣金 + 出库费 + 月度仓储费 | **佣金结算**：类目佣金 + DirectShip 费 |
| 税务 | 平台代扣代缴 | 平台代扣代缴 / 自主申报（口径待确认 C-01） | 平台代扣代缴，自有 VAT 可自主申报 |
| 订单来源 | Seller Lab 导出 / 平台推送 | Noon 自行履约，ERP 主要同步状态与账单 | **FBPI webhook 实时推送** |
| 发货动作 | 发深圳中转仓 | ASN 入库 + 补货 | 24h 内拣货打包、Shipment API 建 AWB、manifest、上门取件 |
| 退货 | 跨境退回不经济，多本地处置 | Noon 处理，Grade A 可重新上架 | 卖家处理退货 |
| 补货逻辑 | 按供价订单节奏补国内/中转仓 | 按 FBN 可售天数 + 入仓周期 + 大促系数补货 | 按自有仓库存 + 平台 SLA 补货 |
| 流量/转化 | 时效弱、适合测款 | Express 标、转化最高、大促准入 | 灵活，适合大件/多平台同库存 |

**三条建模结论：**

1. **库存必须四维**：`SKU × 仓库 × 站点 × 履约模式`，且四态分离：`可用 / 在途 / 锁定 / 不可售`。在途库存不能当现货卖（万墨文档也强调这一点）。
2. **利润必须双引擎**：Global 用「供价 − 到深圳仓成本 − 采购成本」；FBN/FBP 用「售价 − VAT − 佣金 − 履约费 − 仓储费 − 退货费 − 广告费 − 头程摊销 − 采购成本」。**共用一张表会把 Global 算成负毛利。**
3. **仓库主数据不可变**：FBPI 一个仓库码绑定一种履约模式，且已有 FBN/FBP 仓不能转成 FBPI —— 仓库创建时就要定死模式，避免后期改主数据引发账务错乱。

## 4. 核心领域模型（先对齐名词，再写代码）

| 层 | 实体 | 关键字段 / 说明 |
| --- | --- | --- |
| 组织 | 租户 → **店铺** → 站点 → 履约模式 → 仓库 | 一照一店，UAE/KSA 账号独立；店铺需带主体、VAT 号、收款账户、币种 |
| 商品 | SPU → **本地 SKU** → **Partner SKU** → 站点 Listing | 一本地 SKU 可映射多站点多个 Partner SKU；需 EN/AR 标题描述、类目属性、图片、HS Code、原产地、认证、品牌授权、条码 |
| 库存 | 库存台账 / 库存变动流水 | 四态；每次变动留单据 + 操作人 + 时间戳；成本按批次留痕（**核算方法待定，见 Q5**） |
| 单据 | 采购单、入库单、调拨单、出库单、盘点单、组装拆分单、**ASN 货件**、退货单、结算单、费用单、补货建议单 | 全部编号 + 状态机 + 审批流 + 原始字段不删减（导入的原始报文/CSV 行单独存原始表） |
| 财务 | 费用字典（版本化）、汇率、利润公式、周账单、月度仓储账单、回款流水、争议单 | 公式可配置、结果可重算；历史费率版本保留 |
| 集成 | NoonAdapter、通道（API / CSV / 文件 / 手工）、同步任务、webhook 事件日志 | 幂等键、重试、失败补偿、全量留痕 |

> 数据留痕按你的习惯来：**原始字段一律不删减**，清洗/映射另起一层，日志带编号和时间戳，便于事后质疑与回溯。

**单件净利公式草案（FBN/FBP，供对齐用）：**

```
净利 = 含税售价
     − VAT（站点税率，或平台代扣口径）
     − 类目佣金（费率按类目×站点×版本；KSA 有每单最低 1 SAR）
     − FBN 出库费 / DirectShip 费（按尺寸重量价格档）
     − FBN 仓储费（体积 × 库龄档，从月度账单摊销）
     − 退货管理费与退货净损耗（扣除 Seller Protection Fund 补偿）
     − 广告费（CPC，从周回款扣，按 SKU 归因）
     − 头程运费 / 关税 / 清关 / 贴标包材（按批次摊销）
     − 采购成本（批次或移动加权，Q5 定）
     − 收款通道费 / 汇兑损益
```

> ⚠️ 所有费率**报价不含 VAT**，且费率和规则年内会变 —— 这是「费用字典必须版本化 + 结果可重算」的根本原因，不能把费率写进 Java 常量。

| 约束 | 说明 |

| **Q2** | 目前有几个店铺、几个站点、几个仓？（UAE/KSA 是否都已开店、是否同一主体） | 默认 2 店铺（UAE + KSA 独立账号）+ 国内仓 + 深圳中转仓 + FBN 双仓 |

| **Q4** | 是否要做「刊登」模块？还是只用 AI 生成文案 + 人工在 Seller Lab 上架？ | 默认做「CSV 生成 + 校验 + 双语内容库」，**不做全自动刊登**（平台不支持 API 建品） |
| **Q5** | 库存成本核算用哪种：移动加权平均 / 批次（FIFO）/ 个别计价？ | 默认**移动加权平均**，但保留批次流水，后续可切 FIFO |
| **Q6** | VAT 主体与申报方式？是否有 UAE/KSA 本地税号，走平台代扣还是自主申报？ | 默认 `PLATFORM_WITHHOLD`，参数化可切（C-01 待确认） |
| **Q7** | 广告模块要不要做？做到「导入报表算 ACOS」还是「投放控制」？ | 默认只做报表导入 + 归因到 SKU 利润；**不做投放控制**（无公开 API） |
| **Q8** | 利润口径：要不要把头程、关税、包材、汇兑、收款通道费全部摊到 SKU？ | 默认**全摊**（否则利润虚高，中东头程占比不低） |
| **Q9** | 未来是否要扩到 Amazon.ae / Namshi / 独立站？ | 默认**预留适配层但不实现**，避免现在为多平台过度设计 |
| **Q10** | 部署形态：本机 / 私有云 / 阿里云单机？几个人用？要不要移动端？ | 默认单台服务器私有部署，Web 端，5–10 人，移动端放三期 |
| **Q11** | 单据是否需要审批流？采购、调价、费用报销分别几级？ | 默认采购单 1 级审批，其余不做审批只留操作日志 |
| **Q12** | AI 外挂第一个场景选哪个？ | 默认 **「周三 statement 差异核查」**（最痛、最可量化、只读不改账）或 **「英阿双语文案批量生成」**（你已有词库框架，见效快） |
| **Q13** | 现有数据从哪来？Excel 台账 / 1688 抓取工具 / Noon 后台导出？要不要做一次性迁移？ | 默认提供标准导入模板，历史数据只迁 SKU、供应商、期初库存，不迁历史订单 |
| **Q14** | 选品分析（你现在做的双站点数据爬取）要进 ERP，还是保持独立工具？ | 默认**保持独立**，ERP 只接收「开发完成的新品」结果，避免把爬取逻辑塞进核心 |
