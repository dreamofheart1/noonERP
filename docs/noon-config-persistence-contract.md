# 版本化业务参数：持久化接入合同（待 schema v0.5 确认）

本文件是 Codex 与 WorkBuddy 的接入准备，不是已实施迁移；正式字段和业务表由 WorkBuddy 设计。现有实现仅提供历史读取边界、快照值对象和区间校验，未提供数据库 Repository、参数写接口或审计表。

- 读取前对真实业务记录的站点调用 `SiteAuthGuard.requireSite`。Repository 用绑定参数读取指定键和该站点/GLOBAL 的完整历史候选；历史查询不得以当前 status 或 `revoked_at IS NULL` 直接排除已撤销旧行。有效条件为 `from <= businessTime < to` 且 `revoked_at IS NULL OR businessTime < revoked_at`；无结束时刻视为无穷。业务时刻按 Asia/Shanghai 明确传递，原平台时区和实际瞬间另行保留。
- 已选版本、参数键、请求站点、实际范围、值快照、业务时间必须随业务结果在同一事务持久化；建议同时保留解析时刻和快照来源。重算仅从可信业务记录读原快照并再次检查当前站点权限；不接受客户端提交快照，不重新取当前配置。
- 写入口须在服务层限制有效超管或经明确设计、验证的管理权限；普通站点访问权不自动授予配置写权。 GLOBAL 写入尤其不能由单站点授权推导。新版本、撤销信息和操作者审计应在同一事务提交；失败全部回滚。
- 同一 `(config_key, scope)` 写入必须在查候选前先取得持久锁行（包括首次写入时无版本行的情形），使用数据库当前读获得完整同范围候选，再运行 `ConfigIntervalPolicy.requireNoOverlap`，最后插入；所有写路径必须采用同一锁顺序。唯一约束是补充保护，不能替代重叠检查和锁；不得依赖普通快照读或仅锁已有版本行。锁表结构和首行创建竞争由正式 schema/适配器设计并在原生 MySQL 并发测试。
- 区间校验将历史版本的实际结束视为 `min(effective_to, revoked_at)`，均为空表示无穷；半开区间边界相接允许。未来版本在生效之前撤销时无有效区间，但历史行仍保留。该规则不是允许修改/删除旧快照的授权。
- 撤销生效时刻和操作者必须审计，不能用当前状态覆盖历史；追溯性更正的记录时间与业务生效时间是不同维度。本阶段未实现双时态或回溯修正流程，不得靠覆盖旧行假装支持。
- 数据库并发提交、锁等待、回滚、跨站越权、重复提交、审计失败、时区和精度、迁移、快照重算需在实际适配器接入后用隔离 MySQL 测试。本包的内存测试不证明这些数据库行为。
