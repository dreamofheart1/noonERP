# WP1 首阶段：若依身份与站点权限

执行者 Codex；日期 2026-11-18；交叉审核方 WorkBuddy（待独立审查）。本阶段是框架基础，不是完整 ERP 或上线验收。

## 范围与身份边界

沿用若依 `/login` → Redis 登录态 → JWT 过滤器 → `SecurityContext` 中的 `LoginUser`，不新增 Noon 用户表、密码或第二套 token。新增接口没有匿名白名单。`SiteAuthGuard` 只从已认证上下文取 userId，校验内外 userId 一致，并查询 `sys_user` 确认当前未停用、未删除；不信任客户端提交的主体 ID、角色名或菜单通配权限。

- 有效超管 `userId=1` 拥有当前全部站点 AE、SA，无需关联行；不能通过授权接口缩减。
- 普通用户只使用 `sys_user_site` 的显式关联，空授权返回空站点范围、单站访问被拒。
- 站点列表严格匹配 AE、SA，不接受空值、通配符、小写、尾空格或未知代码。当前单店铺双站点，扩站/多店铺必须同步主数据、站点清单和测试。
- 不把站点授权缓存到 LoginUser/Redis。下一次校验重新查库，撤权不需要重新登录；已开始的事务/查询不承诺被追溯取消。MySQL 默认 REPEATABLE READ 的长事务仍可能维持旧快照，后续业务写路径须在短事务边界再校验并设计锁定策略。
- 账号状态的实时检查只针对本站点闸门，未改变若依其他模块旧 token 的停用语义。
- 后台任务无登录上下文时拒绝。AI/任务机器账号认证、主体类型和授权委派尚未接入，不支持传任意 userId 代替认证；后续不得借用超管或手工拼接 LoginUser 运行任务。

## 接口与事务

均需若依已有 Authorization 请求头。

| 方法 | 路径 | 输入与结果 | 权限 |
|---|---|---|---|
| GET | `/noon/sites` | `data: ["AE", "SA"]` 或当前显式范围（可能为空） | 有效登录用户 |
| GET | `/noon/site-grants/{userId}` | 指定有效用户当前站点列表 | 有效超管 |
| PUT | `/noon/site-grants/{userId}` | JSON 数组，如 `["AE"]`；`[]` 撤销全部 | 有效超管 |

PUT 是**全量替换**，不是增量追加；不提供隐式默认授权。目标须存在且有效，不能覆盖超管；null 请求、未知站点等失败时不得修改旧授权。服务层独立执行超管检查，不靠 Controller 注解作为唯一边界。

替换在 Spring 事务内锁定目标 `sys_user` 行，防止同一目标的并发替换混成集合；随后用 `FOR UPDATE` 当前读读取原授权（避免 MySQL RR 等锁后读旧快照），删除、插入、`sys_user_site_audit` 的 actor/target/前后值/北京时间同事务提交，审计失败回滚授权。同值替换无额外审计行。Controller 另沿用若依 `@Log` 操作日志。客户端错误沿用若依 AjaxResult 的 `code`（例如 403/400），不表示 HTTP 状态码已改变。

## 数据库接入

脚本：`yx-erp/sql/noon_wp1_site_auth.sql`。不自动运行、不触碰生产。

1. 全新安装先运行若依基础 SQL，再在隔离开发库运行本脚本；已有若依库仅运行本脚本。不要直接叠加旧 Noon schema 中同名系统表 DDL。
2. 先确认 `sys_user` 为 InnoDB、`user_id` 为兼容 BIGINT，且 `sys_user_site`、`sys_user_site_audit` 均不存在。若同名表已存在，先核对结构/历史版本，不能用 IF NOT EXISTS 掩盖差异。
3. 本脚本只新增两表，不回填授权、不改用户与全局参数。没有已确认的旧用户站点数据，因此没有编造自动拆分/迁移映射；既有业务库迁移另做专项。
4. MySQL DDL 非整体事务：第二张表建失败时第一张可能已存在，须人工核对隔离库并修复，禁止重复盲跑或直接丢弃已写授权。审计时间由应用按 Asia/Shanghai 显式写入，站点比较使用 ascii_bin。
5. 尚未在真实 MySQL、Redis 或全应用启动环境验收。H2 测试移除字符集/排序声明后运行同份增量 DDL，不能替代 MySQL 兼容性验证。

## 后续业务接入的强制合同

`SiteAuthGuard` 已可由服务直接调用，**尚无业务表/业务查询，因而没有声称全库已自动站点隔离**。后续每个业务工作包必须逐入口满足以下条件：

- 列表/统计/导出：服务取得 `allowedSiteCodes()`，SQL 使用绑定参数 IN；空集合用 `WHERE 1=0`，绝不能省略站点条件。若依部门过滤和菜单权限仍须保留，和站点范围取交集。
- 详情/下载/更新/删除：由记录 ID 查询其真实站点，调用 `requireSite(realSiteCode)` 后才返回/变更业务数据；不能以请求体里声称的 AE 绕过实际 SA 记录。SQL 更新同时绑定 ID、站点和版本。
- 跨表关联：主从表都绑定同站点；不得仅过滤主表却串入其他站点明细。批量导入/写入先检查全批涉及站点，再开始正式写入事务。
- 后台任务、AI、异步执行、重新计算：单独接入明确认证主体及站点，异步线程没有用户上下文时不能自动降级为全站。正式写入前再校验权限。
- AI 后续写隔离暂存层；审批通过才转正，规则不明确时人工。未批准数据不得参与库存/利润/账单计算。本包未实现审批或平台写能力。
- 配置历史覆盖与统一中国时区另包实施；平台原始时区/偏移及实际截止瞬间必须保留，不擅自重定义平台期间。
